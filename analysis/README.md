# Analyze Phase | Understand the Paycheck Requirements

**SDLC progress:** [Start Here](../README.md) → **1 Analyze** → [2 Design](../design/README.md) → [3 Construct (Practice)](../src/README.md) → [4 Test (Practice)](../tests/README.md) → [Submit](../README.md#submit-your-assignment)

## Purpose

The Analyze phase is where you make sure you understand **what the solution must do** before deciding exactly how to represent the solution.

For this assignment, the Guidelines and Rubric is the official source of requirements. The provided [Software Requirements Specification (SRS)](paycheck_calculator_srs.md) organizes those requirements into a form commonly used during software development.

The Analyze phase does **not** create a graded deliverable. It prepares you to create the graded flowchart and pseudocode in the Design phase.

## What You Will Use

- Module Three Assignment Guidelines and Rubric in D2L Brightspace
- [Paycheck Calculator SRS](paycheck_calculator_srs.md)
- [Software Development Worksheet (SDW)](../paycheck_calculator_sdw.md) for recommended working notes

## What You Will Do

1. Read the complete Module Three Assignment Guidelines and Rubric.
2. Read the [SRS](paycheck_calculator_srs.md).
3. Identify the program's input, processing rules, decision point, and output.
4. Pay special attention to the boundary at **40 hours** and the phrase **above 40 hours**.
5. Record concise notes in the Analyze section of the [SDW](../paycheck_calculator_sdw.md), if useful.
6. Compare your understanding with the requirements before moving to Design.

> [!IMPORTANT]
> Do not add requirements that are not stated in the assignment. For example, the assignment does not specify how invalid or negative input must be handled. Focus first on the required paycheck calculation.

## Check Your Work

Before moving to Design, you should be able to explain in your own words:

- What value the program needs from the user
- Which pay rates apply
- What makes the program choose one calculation path instead of another
- What result the program must produce
- Why 40 hours is an important boundary case

You do not need Python code to answer these questions.
